The agent loop

Each ticket takes several reasoning steps. When a result changes the picture, like a parcel that never arrived, the agent changes its plan.

PlanActObserveRe-planDecideSelf-checkGuardrailVerify
🗄️

Order database

Item, price paid, serial number and tracking ID from a SQLite store.

get_order()
🚚

Courier API

A live HTTP service for delivery status. Times out? It retries, then escalates safely.

track_shipment()
📜

Policy RAG

Retrieves the exact clause behind every decision, and quotes it back.

search_policy()
🧠

Customer memory

Every past ticket is remembered. Repeat returners can't hide.

get_customer_history()
📷

Proof request

No photo of the damage? The agent asks before it decides.

request_proof()
🧾

Refund ledger

Checks for an existing refund before paying. Every refund is written, then read back to verify. No double payouts.

check_refund_status()
🛡️

Guardrails the AI can't override

Over Rs 2,000, repeat returner, serial mismatch, duplicate refund, prompt injection or system failure: the code blocks or holds it for a human, whatever the model says. Every human decision is logged with reviewer and timestamp.

apply_guardrails()
